サポート

対象バージョン 1.6 / お問い合わせは GitHub Issue へ

エクスポートがうまくいかない場合、原因はいくつかのパターンにほぼ絞られます。まずは以下の対処をお試しください。解決しない場合は、最後のセクションの内容を添えてご報告いただけると調査できます。

最初に確認すること

  • X にログインした状態で x.com/i/bookmarks（ブックマークタグを使っている場合は x.com/i/history）を開いてください。
  • エクスポート中はそのタブを前面のままにしてください。ページを自動スクロールして読み込む仕組みのため、バックグラウンドのタブでは追加の読み込みが止まることがあります。
  • ページを再読み込みしてからもう一度実行してください。長時間開いたままのページは、結果が空になる原因として最も多いものです。

よくある症状

「x.com/i/bookmarks を開いてください」と表示される

この拡張機能が動作するのは https://x.com/i/bookmarks と https://x.com/i/history のみです。twitter.com のアドレスや X の他のページでは動きません。ブックマークページ自体を開いた状態でアイコンをクリックしてください。

結果が空になる、一部の投稿が入らない

期間の絞り込みは投稿された日付が基準で、ブックマークした日ではありません。2023年の投稿を昨日ブックマークした場合、「今週」の範囲を指定すると対象外になります。まず開始日・終了日を両方とも空にして全件書き出し、そこから絞り込むのがおすすめです。

途中で止まる

拡張機能はタイムラインを自動スクロールし、X が次の投稿群を返すのを待ちます。タブがバックグラウンドに回ったり通信が滞ったりすると、X からの配信が止まり、その時点でエクスポートが終わります。タブを前面に戻して実行し直してください。再実行しても同じファイルが作り直されるだけで、二重に増えることはありません。

まったく書き出されない

X の画面構造は頻繁に変わり、その変化で読み取り用スクリプトが投稿を認識できなくなることがあります。まず再読み込みと再試行をお願いします。それでも空のままなら拡張機能側の不具合ですので、ご報告ください。

画像や動画が ZIP に入っていない

メディアは X 上の元ファイルへのリンクとして記録され、ダウンロードはされません。画像は ## Media 見出しの下に Markdown の画像リンクとして、動画は元の投稿へのリンクとして残ります。ファイルは軽いままですが、メディア本体は X 側にあります。

ファイル名が途中で切れている

ファイル名は本文の先頭50文字と投稿 ID から作られ、Windows や macOS で使えない文字はアンダースコアに置き換えられます。本文は全文がファイルの中に入っており、短くなっているのは名前だけです。

毎回保存先を聞かれる

これは意図した挙動です。拡張機能は ZIP をブラウザに渡して保存先を選んでもらう方式で、勝手にどこかへ書き込むことはありません。

不具合を報告する

GitHub の Issue からご報告ください。以下の項目を書き写していただけると、再現の手がかりになります。

拡張機能のバージョン: 1.6
ブラウザと OS: 例）Windows 11 の Chrome
使用したページ: x.com/i/bookmarks または x.com/i/history
指定した期間: 開始日・終了日、または未指定
起きたこと: 期待した結果と、実際に起きたこと
コンソールのエラー: DevTools のコンソールに出た赤い文字

ブックマークの本文そのものは貼らないでください。エクスポートの不具合を直すのに投稿の内容は不要で、GitHub の Issue は公開されます。

対応について

MIT ライセンスの個人プロジェクトを空き時間で運営しているため、返信までお時間をいただくことがあります。上記の情報が揃った報告がいちばん早く修正につながります。窓口は GitHub Issue のみで、サポート用のメールアドレスは用意していません。やり取りが公開の場に残るので、同じ問題に当たった方が答えを見つけられます。

機能の要望やプルリクエストも同じ場所で歓迎しています。拡張機能全体で数百行の JavaScript なので、手を入れやすい規模です。
